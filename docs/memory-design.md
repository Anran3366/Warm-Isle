# 记忆系统设计（v2）

> 目标：把「记忆」和「知识库」合并成一个以“能用来关心对方”为标准的记忆库。
> 状态：P1–P3 已实现并上线（2026-10-28，提交 `928971f` / `f772464` / `c0f8d5a`）；P4 知识库「设定」用途、P5 向量检索未做。

---

## 1. 核心判断

陪聊机器人的记忆价值 **不在于信息完整，而在于能不能转化为关心或对话**。

| 信息 | 记不记 | 理由 |
|---|---|---|
| 工作：在字节做后端 | ✅ | 长期背景，随时可用 |
| 昨天加班到 10 点 | ✅ | **可以追问「昨晚又熬夜了吧」** |
| 不喜欢吃香菜 | ❌ | 她不会点外卖，这条永远用不上 |
| 今天吃了牛肉面 | ❌ | 一次性，无法行动 |
| 妈妈住院了 | ✅ | 高情绪 + 可跟进 |
| 最近在准备考研 | ✅ | 有时效，可关心进度 |

结论：**判断标准 = 这条记忆能不能支撑一次关心、追问或延续话题**。

## 2. 记忆分类

```sql
memories (
  id
  type        -- profile | event | relation | world
  subject     -- user | bot | third:<名字>
  key         -- 归一化主题（工作/城市/健康/睡眠…）
  value       -- 具体内容
  source      -- chat | doc:<id> | manual
  importance  -- 0~1，取「可行动性」评分
  confidence  -- 0~1
  emotion     -- -1~1，事件的情绪色彩
  first_seen / last_confirmed
  expires_at  -- 有时效的事实到期时间
  follow_up_at        -- 主动回忆时间（可空）
  follow_up_state     -- none | pending | done | skipped
  action_hint -- 可行动提示，如「今晚提醒早点睡」
  status      -- active | archived | expired
  superseded_by
)
```

### 四类记忆

| 类型 | 含义 | 例子 |
|---|---|---|
| `profile` | 长期稳定属性 | 城市、职业、家人、慢性病 |
| `event` | 有时间点、有情绪的事 | 加班到 10 点、面试、吵架、生病 |
| `relation` | 你们之间的约定/称呼 | 她叫你老板；约定周末聊 |
| `world` | 来自文档的设定 | 小说人物关系、世界观 |

> 台词/语气样本不进本表，仍走 `style` 轮换。

## 3. 抽取规则（D，v2）

夜间整理时，对每条候选记忆打「可行动性」分：

```
可行动性 =
    0.40 × 能否转化为关心/追问
  + 0.25 × 情绪强度
  + 0.20 × 时效性（越近期越高）
  + 0.15 × 稳定程度（长期属性加分）
```

| 得分 | 处理 |
|---|---|
| ≥ 0.65 | 高价值：写入 + 生成 `follow_up_at`（原定 0.7，2026-10-28 下调） |
| 0.4 ~ 0.65 | 普通：写入，不主动提 |
| < 0.4 | 丢弃 |

### 记 / 不记清单

**记**

- 生活状态：加班、熬夜、出差、生病、生理期
- 情绪事件：吵架、被骂、面试、考试、家人健康
- 稳定属性：工作、城市、家人构成、长期目标
- 关系信息：称呼、约定、共同话题

**不记**

- 一次性消费：今天吃了什么、买了什么
- 无法行动的偏好：不爱吃香菜、喜欢蓝色
- 天气、时事、泛泛而谈的感慨

> 例外：如果「不爱吃香菜」是在“要不要一起吃饭”的语境里说的，可以记为 `relation`（你们之间的饮食约定），但不单独作为偏好。

## 4. 主动回忆（新增）

### 触发

夜间整理时，对 `type=event` 且 `importance ≥ 0.65` 的记忆计算 `follow_up_at`：

| 事件类型 | follow_up_at |
|---|---|
| 加班 / 熬夜 | 次日 21:00–22:30 |
| 面试 / 考试 | 次日 19:00–21:00 |
| 生病 / 不舒服 | 次日上午 10:00 |
| 吵架 / 情绪低落 | 2 天后 20:00 |
| 冷战 / 你没回她 | 次日 20:00 主动服软 |
| 一般事件 | 不主动提 |

### 关系类主动回忆

`type=relation` 的记忆也可以主动触发，但语气不同（不是“关心”，是“关系维护”）：

| 场景 | 行为 |
|---|---|
| 上次吵架、用户先低头 | 2 天后主动软化，不再翻旧账 |
| 用户说过「别烦我」 | 3 天内不主动，之后轻描淡写试探 |
| 约定（「周末聊」） | 到点主动提起 |
| 用户长期冷淡（3 天未回） | 不追问，只发一条低压力消息 |

约束：关系类主动回忆**不与事件类叠加**，每天最多 1 条。

### 发送

主动消息系统在 tick 时：

1. 查 `follow_up_at <= now` 且 `state=pending` 的事件；
2. 检查约束：当日主动消息未超限、不在免打扰时段、用户最近 2 小时没说话；
3. 用事件内容生成一句关心（提示词要求：**顺着事实问，不要提“记忆”**）；
4. 发送后置 `state=done`；用户当天已提过该话题则 `skipped`。

### 示例

```
（前一天 22:40）你：今天加班到十点，累死了
（次日 21:30）
她：昨晚又熬到十点，今天早点睡吧，别又拖到十二点
```

### 约束

- 同一事件只主动提一次；
- 每个用户每天最多 2 条主动回忆（其中关系类最多 1 条，不挤占早安/晚安额度可另配）；
- 用户明确说“别问了” → 该 key 全部 `skipped`；
- 主动回忆失败（模型拒绝/空回复）不重试，置 `skipped`。

## 5. 被动回忆（检索）

聊天时：

```
用户这句话 → 归一化 → 关键词 + 二元组打分
  score = 相关度×0.5 + 重要度×0.3 + 新鲜度×0.2
  取 top 8~12，总长 ≤ 1200 字
```

拼进 prompt 分三块：

```
【关于对方】
- 工作：在字节，做后端（3 天前确认）
- 健康：胃不好，不能吃太油

【你们之间】
- 她叫你「老板」
- 上次吵架是因为你三天没回消息

【最近发生】
- 10-27 加班到 22:00（已关心过）
- 10-26 面试（结果未提）
```

没有命中时只带「最近事件 1~2 条」。

## 6. 每日整理流程（00:05）

```
当天 messages
   ↓ 1. 生成 episode（当天摘要 + 事件列表 + 情绪）
   ↓ 2. 抽取候选记忆，按 §3 打分
   ↓ 3. 冲突合并：同 subject+key 新值 → 旧记录 archived + superseded_by
   ↓ 4. 计算 follow_up_at（§4）
   ↓ 5. 维护：expires_at 到期 → expired
   ↓            强度按遗忘曲线衰减，<0.15 → archived（pinned 不衰减）
```

内存保护沿用现有规则（可用 <500MB 暂停）。

### 6.1 记忆强度：连续遗忘 + 复习 + 周期日（2026-11-04）

原来的实现是「90 天未确认 → 每晚 importance ×0.85，<0.3 归档」，两个问题：

1. **它挂在夜间整理末尾**，而夜间整理在「昨天消息 < 2 条」时直接 return——越没人说话越不衰减，
   彻底沉默的用户记忆永远 active，正好和遗忘相反；
2. **它不是曲线是悬崖**：过 90 天后 0.85^8≈0.27，八九天内集体归档。

现在换成每条记忆各自的指数衰减（`memory/MemoryStrength.java`）：

```
strength(t) = strength₀ · exp(−Δt / τ)
τ = 类型底数 × (0.4 + 1.5 × importance)
类型底数：event 2.2 · profile 2.4 · relation 5.0 · world 12.0（天）
```

| 状态 | 判定 | 表现 |
|---|---|---|
| 正常 | strength ≥ 0.35 | 正常注入 |
| 快忘了 | 0.15 ≤ strength < 0.35 | 检索排位靠后，星图变灰 |
| 忘了 | strength < 0.15 | 归档，不再注入 |

校准基准：importance≈0.4 的 event 约 2.2 天减到 1/e、4 天出头跌破 0.15——
「陌生人的一两句话，三五天就忘了」。

**复习效应**：同 subject+key 又被说了一次（`upsert` 命中同值）→ strength 直接回 1.0，
`recall_count+1`。「周一说的、周五只剩 0.2、周六再说一次」就是回满。
被检索命中并注入 prompt（被动想起）只回 `+0.06×(1−s)`，避免「被搜到一次就永远满格」。

**不能忘的事**：`pinned=1` 的记忆不衰减。文本里出现「生日/出生/诞辰」且能认出日期
（`10月26日`、`10-26`、`3/5`）时自动钉住并记 `recur_md=MM-DD`；当天由
`ProactiveRecallService` 优先发一条生日祝福（独立于 follow_up 状态、不占日常额度），
`recur_last` 记下今年已发，同年不重复。

**衰减独立调度**：`NightlyMemoryService.decay()` 每天 00:02 遍历 `memories` 里的所有用户，
不看昨天有没有消息——这是和旧实现最关键的区别。

**星图**：`GET /api/memories/graph` 返回节点（带实时 strength）与派生边
（同 subject 锚点 / 同 baseKey / 向量余弦 ≥0.55 的近邻）。后台「记忆星图」页默认展示**这个账号下所有聊过天的人**（右上角可按人筛选，`/api/memories/graph/users`
给下拉数据），连边只在同一个用户内部生成，不会把两个人的隐私连成一片。
它是一片刻意压扁的**旋涡星系（记忆银河）**：
所有记忆（含已归档）按强度从强到弱排序，**半径只看排名**（面积均匀，任意条数都能铺满盘面，
不设条数上限），强度决定亮度和大小；旋臂数随条数增长（3→7 条），角度按对数螺旋拧出。
每颗记忆自带一圈尘埃，另有星尘粒子撑出星云形状；已忘记的记忆用灰色、更暗，但仍在图上。强记忆旁边飘一行淡淡的文字（记忆 key），整体像一片会自转的记忆海。
官网/个人主页的演示星图是同一个渲染器的静态化版本（`site/*/assets/star-map.js`），
首次加载会请求 `GET /api/public/memory-stats`（免登录、60 秒缓存、只返回 total/users/fading/pinned/byType），
拿到后按真实数量重建节点；接口不可达时退回脚本里的默认值，页面不受影响。
拖动旋转、滚轮缩放、点星看详情、可手动钉住；**鼠标悬停**时只亮这颗记忆和它的一跳邻居
（subject / baseKey / 向量边），其余压暗到 18% 并把链路连线画出来；HUD 显示条目数 / 平均强度 / 自转角。

## 10. 风险

| 风险 | 对策 |
|---|---|
| 记错被放大 | 带 source 与 confidence，后台可删；置信度 <0.6 不注入 |
| 主动回忆变骚扰 | 每事件一次、每天上限、免打扰、可全局关闭 |
| 过度记忆感 | 后台可查看全部记忆；支持「这个别记」 |
| 成本 | 整理在夜间谷价；检索本地计算不花 token |
| 迁移风险 | facts 表保留只读，双写一周再切 |

### 与设计稿的有意偏离

1. **主动回忆额度独立于 `push.dailyLimit`**（设计稿说「可另配」）：不挤占早安/晚安额度。
2. **超过 3 天的 follow_up 不再补发**：避免翻旧账，直接置 `skipped`。
3. **文案带兜底**：模型输出含「记忆/记录」时不用改写后的半句，直接换确定性兜底句。
4. **`kind` 由模型给出，缺失时按关键词兜底**（加班/面试/生病/吵架/冷战/约定）。
5. **00:05 与知识库解析同窗口**：Spring 默认单线程调度器，两个任务顺序执行，不会同时压内存。

### 上线时的实际观察

- 迁移 23 个用户、58 条记忆；夜间整理试跑 14 个用户，写入 27 条、丢弃 4 条、生成 14 个 episode。
- 可行动性最高 0.68，原定 0.7 阈值下当天没有 follow_up；2026-10-28 按所有者「宁可多问一句」下调到 **0.65**，同类事件现在会排到次日关心。
- 线上免打扰为 `push.quiet = 00:30–07:00`（2026-10-28 所有者已改，不是全天静默）；落在该时段的主动回忆/生日祝福会顺延到 07:00 之后的首个 tick。
